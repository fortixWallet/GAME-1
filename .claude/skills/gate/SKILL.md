# Гейт: три режими, один закон

| Режим | Команда | Коли | Час |
|---|---|---|---|
| quick | `bash .claude/verify_build.sh --quick` | після кожної правки | ~7 с, БЕЗ вікон |
| c2 | `bash .claude/verify_build.sh --c2` | ітерації по справі 2 | ~35 с |
| full | `bash .claude/verify_build.sh` | ПЕРЕД комітом, обов'язково | ~3 хв |

## Закони
- Перед запуском: `pkill -f godot; pkill -f verify_build; sleep 2`. ДВА гейти
  паралельно б'ються за GPU і валять тести випадково (оплачено годинами).
- Вікна тестів ідуть за екран (`--position 4000,100` вже в скрипті) — якщо
  Віктор бачить «гру по колу», щось запущено не через цей скіл. Убити все.
- Гейт червоний → команда `git commit` НЕ виконується. Крапка.
- Очікувані числа (facts=N/M, total=N) міняються ТІЛЬКИ свідомо, окремим
  рядком у коміті, після ручного запуску тесту й розуміння різниці.
- Тести живуть у СЕКУНДАХ, не кадрах: за екраном fps без vsync, `frame_post_draw`
  летить швидше за твіни. Чекання — `create_timer`, і `await` на async-функціях.
- Правило 17: перевірка спершу друкує СКІЛЬКИ побачила; нуль знахідок при нулі
  переглянутого = поломка перевірки. Новий тест мусить мати негативний прогін.

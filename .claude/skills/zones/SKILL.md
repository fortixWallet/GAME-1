# Зони Bureau: спершу з'ясуй, у ЧИЇХ частках координата

Рушій: сцени = словники в `Bureau/scenes/*.gd`. Три системи відліку
(TECHNICAL_PLAYBOOK + LESSONS «text_box шару-оверлея»):
1. **зони `"rect": [x, y, w, h]`** і **шари `"pos"`** — частки ФОНУ сцени;
2. **`"texts"` бланка** — частки СПРАЙТА бланка;
3. **`text_box` шару-оверлея** (overlay_blank, h=1.0, anchor form) — частки
   ШАРУ 2215×1246, НЕ екрана: коефіцієнти ×1.465 по x, ×1.269 по y.
   Метод: поставити бокс → кадр → заміряти факт і ціль → перерахувати.
4. Міст клікає частками ВІКНА: `x_вікна = (x_фону − 0.067)/0.866`.

## Процедура
1. Сітка часток на кадр (PIL, лінії кожні 0.05, підписати) → Read → зняти
   точні частки; або замір кольором по пікселях з ПРИВ'ЯЗКОЮ до очікуваного
   місця, не глобальною кластеризацією (вона хапає сусідню латунь).
2. Правило 31 (сузір'я): перед зсувом шару — grep усіх залежних зон/move-цілей;
   рухати ВСЕ разом. Правило 32: фон не кропити/не тягнути ніколи.
3. Правило 42 (ергономіка): верхні ~9% і нижні ~13% екрана — territory HUD,
   зони туди не заходять; коридор ≥4% висоти між сусідніми зонами.
4. Перевірка: `tools/check_zones_alive.py` + `tools/check_ergo.py`, потім
   живий клік мостом (скіл playtest) — зона мусить ДІЯТИ або ГОВОРИТИ
   (правило 34; мовчазний ковтач = дефект).

## Закони
- pick найменшої зони нема — зони перекриваються порядком у списку: перший
  збіг виграє; needs/done вимикають зону, а не ховають (клік по видимій
  картці без живої зони = ковтач, урок 22.08).
- Що сказано в say — мусить бути ВИДНО в кадрі (правило 22).

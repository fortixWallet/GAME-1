## I.3. Десять законів виробництва

1. Носій обирається раз; розворот — за заміром.
2. Стани — від референсу; наближення — кропом. Слова про камеру заборонені.
3. Кожен кадр звіряється числом до вставки (≥0.3).
4. Факт без кадру не існує (`shown_in` обов'язковий).
5. Один предмет — одна проста дія; складність у здогаді.
6. Усе на одному екрані; кожен перехід — податок.
7. Еталон перед серією; найдешевша гіпотеза першою.
8. Кожна перевірка друкує, скільки побачила, і має негативний тест.
9. Точковий тест під час роботи; повний гейт раз перед комітом.
10. Три підписи «готово»: казуал сформулював · без застрягань >5 хв · око Віктора.

## II.2. Розподіл праці

**Віктор (UI, руками):** стиль і **майстер-кадр** кожної речі — робота ока.
**Клод (API):** усе після затвердженого майстра — стани, кропи, HD, вирізки,
вставка, перевірка числом. Причина: тільки API дає детермінований референс і
**автоматичний замір**; без числа кадр не ставиться.

## II.3. Вимоги до майстер-кадру

1. 4K+ (усі макро — кропом із нього).
2. Річ ціла, поля ≥10% з кожного боку (щоб стани мали куди рухатись).
3. Одне джерело світла, тепле, справа-згори.
4. Контактна тінь — річ стоїть, не висить.
5. Тло — наше сукно/стіл (студійне сіре — лише для 3D-порталу).
6. Жодного тексту в кадрі.
7. Деталь-доказ фізично присутня (клеймо, подряпина, шов).

# ЧАСТИНА III. АНАТОМІЯ ПРЕДМЕТА

## III.1. Три шари

```
ШАР 1 — МАЙСТЕР (4K, у сцені)      → фон екрана
ШАР 2 — СТАНИ (від майстра, ≥0.3)  → плити, що заміщають майстер
ШАР 3 — РУХОМІ ДЕТАЛІ (вирізки)    → спрайти поверх плити
```

## III.2. Стан чи вирізка

| Дія | Спосіб | Чому |
|---|---|---|
| відкрити кришку · зняти дошку · перевернути · висунути шухляду | **СТАН** | змінюється половина кадру, тіні, перспектива |
| повернути ключ · викрутити шуруп · зсунути засувку · зняти портрет | **ВИРІЗКА** | мала жорстка деталь, решта кадру не змінюється |
| наблизити клеймо | **КРОП** майстра (HD ×2) | генерація зробить нову зйомку |
| косе/нічне світло | **СТАН** | освітлення міняє всю сцену |

## III.3. Рецепт вирізки (перевірений)

1. Два стани: «деталь на місці» і «деталі нема» (порожнє гніздо, Ш3).
2. Різниця кадрів → маска: `abs(A−B).sum(axis=2) > 30`, MaxFilter(9) +
   GaussianBlur(2). Брати **найщільніший згусток** (профілі щільності по осях),
   не глобальний bbox — інакше притягне сусідні деталі.
3. Різати **з тінню**, на однорідному тлі (на переходах вирізка брудна).
4. Центр міряти **якорем** (±38 px від очікуваного), не глобальним кластером.
5. Перевірка: покласти назад у той самий піксель — шва бути не має.

## III.4. Посадка спрайта на фон

- Позиція — у **частках плити**, не в пікселях екрана.
- Тінь — у самій вирізці (multiply), не окремим овалом.
- Обертання — навколо **виміряної осі** (шарнір, гвинт), не центру спрайта.
- Ловець вводу — **остання дитина екрана** (GUI-пікінг зворотним порядком;
  z_index не діє).
- **Хотспот вмикається лише у своєму стані** (урок: конверт з'їдав кліки по кришці).

# ЧАСТИНА VI. ЯК РОБИТЬСЯ ЗАГАДКА (на прикладі шафки)

1. **Питання:** як відкрити шафку без ключа?
2. **Відповідь ВИДНА:** три клямки різної затертості — намальовано в майстрі,
   не описано текстом.
3. **Дія проста:** клік → поворот на 30° (вирізка).
4. **Помилка = подія:** невірний порядок → клац, усі повертаються, звук. Без
   покарання і без докору.
5. **Нагорода одразу:** лупа → наступний клієнт її вимагає (за 3 хвилини).
6. **Тест чесності:** казуал за 60 с відтворює ланцюг уголос («найзатертіша —
   та, яку відкривали найчастіше — отже перша»).
7. **Негативний тест:** підсунути кадр з однаковою затертістю — загадка мусить
   стати нерозв'язною. Вгадав усе одно → це перебір, не дедукція.

# ЧАСТИНА VII. МЕТРИКИ ПРОТОТИПУ (міряти, не вірити)

| Метрика | Як | Червона зона |
|---|---|---|
| Час до вердикту | лог поява→печатка | p50 <90 с = сортування |
| Джерел використано | лічильник (річ/лупа/реєстр/записник/поворот) | >50% випадків ≤1 |
| **Навігація vs міркування** | секунди переходів проти «дивиться, не клікає» | **навігація >30%** |
| Хибні вердикти | лог | <10% (нема напруги) або >40% (не читається) |
| Затримка рішення→підтвердження | лог | >20 хв без часткового сигналу |
| **Справжні удари** | тестер тисне клавішу на «о, є» | збіг із планом <30% |
| Ретеншн | де відклав мишу | пауза >30 с |
| Пост-інтерв'ю | «назви найприємніший момент» | не збігається з планованим піком |

**Негативний тест звуку:** збірка без пера, монет і клацань, два тестери.
Нема різниці — ставка на мікро-удари хибна, бюджет іде в глибину атестації.

# ЧАСТИНА VIII. ЧЕРГА (строго по порядку)

1. **Стиль:** Віктор обирає (гуаш / олія / туш+акварель) → стиль-суфікс
   фіксується → `case_desk.png` перегенеровується як новий стиль-якір.
2. **Атом COUNTER у новому стилі:** ложка, 3 стани, HD, реєстр на тому самому
   екрані → казуал → три підписи.
3. **Вступ:** двері (М+С+В) → кабінет → скринька (є) → заповіт.
4. **Потік дня 1:** наперсток, ланцюжок ⌐7, табакерка з лупою.
5. **Шафка інструментів** + негативний тест.
6. **Перлина «Келих»** (4 кроки) + атестат із частковою правотою.
7. **Вечір і ніч:** гросбух, доріжка, портрет, картка №1.
8. **Заміри прототипу** (Частина VII) → рішення, чи структура жива.
9. Дні 2–6 за `GAME.md` §5, кожен по цьому ж циклу.

**Стоп-правило:** наступний пункт не починається, поки попередній не взяв три
підписи. Пункт, що не бере, — вирізається, а не дотягується.

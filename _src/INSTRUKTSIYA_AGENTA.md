## 3. ЗАЛІЗНІ ПРАВИЛА (порушення = переробка всього)

**П1. ЖОДЕН видимий піксель не створюється кодом.** Панелі, кнопки, рамки, шкали, курсор, полум'я, темрява, підсвітка hover — усе генерується арт-сервісами як зображення. Код лише збирає, рухає, повертає і фейдить ГОТОВІ картинки. Ефекти — теж мальовані оверлеї (темрява = намальований шар мороку, не чорний ColorRect; glow = друга версія спрайта з відблиском, не шейдер). Єдиний виняток: ТЕКСТ рендериться шрифтом, але завжди НА намальованій поверхні. Це правило народилося з провалу НЕЛЮДА — StyleBoxFlat-панельки поверх мальованого фону = «1998 рік».

**П2. Сцена = ШАРИ + СТАНИ.** Кожен екран: мальований фон + окремі мальовані елементи зверху. Кожен інтерактивний об'єкт — окремий спрайт у ВСІХ станах і частинах: шухляда закрита/висунута/нутро; стрілки годинника — окремі спрайти (код їх тільки обертає); лампа горить/згашена; портрет рівно/криво; печатка піднята/притиснута/відбиток. Розшарування — прийомом NBP «edit, don't re-roll» з еталонного кадру: 99% пікселів успадковуються, стиль не пливе між шарами.

**П3. НУЛЬ КОДУ до затвердження арту.** Порядок жорсткий: еталон-кадр стилю → «оце воно» від Віктора → карта розшарування (документ: кожен екран по шарах/станах) → арт-макети ВСІХ екранів картинками → затвердження → тільки тоді код, зобов'язаний виглядати як затверджений кадр. Ніяких «тимчасово накидаю кодом» — тимчасове стає постійним.

**П4. IP-чек кожного обличчя і концепту (урок Фродо).** Персонаж «босий» вийшов копією Елайджі Вуда — файл заборонений. Кожне згенероване обличчя/предмет — реверс-перевірка на схожість із відомим IP ДО того, як піде в продакшн.

**П5. Агентські плейтести — мірило якості.** Казуальний агент-плейтестер проходить кожну справу без застрягання >5 хв і без зовнішньої допомоги — інакше справа переробляється. Кожен висновок гравця має ≥3 незалежні дороги (правило трьох доріг). Тестуй реальними кліками (xdotool), не синтетичними сигналами — синтетика пропускає баги перекриття вводу (доведено багом «зависло на хустці»).

**П6. Стиль — тільки з `style.py` + стиль-референси.** Одне джерело. Міняється стиль — міняється ОДИН файл. Trait-locking: риси персонажа описуються дослівно однаково в кожному промпті (не синонімізувати).

**П7. Помилка гравця — подія, не стіна.** Гра ніколи не показує «неправильно» і ніколи не зупиняється: помилковий атестат породжує наслідок. Гра ніколи не каже відповідь до печатки гравця.

**П8. Ключі API — гроші.** Не комітити в публічний репозиторій, не показувати. Якщо засвітився — перевипустити.

## 4. ДИЗАЙН ГРИ — ЩО ВЖЕ ПРИДУМАНО І УЗГОДЖЕНО

Повний текст — у чотирьох документах `_src/design/`. Конспект:

- **Ідея:** університетське місто ~1900-ті, гравець успадкував Бюро атрибуції. Кожна річ — детективна справа; вирок — АТЕСТАТ (походження/справжність/особлива примітка), заповнюється пером, печатка+сургуч — пік дофаміну. Вибір з відкритих у справі варіантів (патерн Golden Idol) — тому доступно всім.
- **7 типів справ:** клейма · прохання-пошук · річ-механізм («У РУКАХ», наш 3D-конвеєр) · шифр-лист · два свідчення · проти авторитета · «не підлягає атрибуції» (жах, макс. 1/день).
- **Сюжет «ПЕЧАТКА»:** зло не в речах — зло в ПЕРЕДАЧІ; печатка — двері; бюро — механізм. Продавець ходить 70 років з різними обличчями й однією рукою. Попередник зрозумів і ПЕРЕСТАВ ставити печатки — тому «зник». Три холодні хвилі (усі — висновки гравця, не текст): «власники вмирали» → «ця річ стояла тут увесь час» → «дверима був я» (лічильник власних печаток).
- **Структура:** 7 днів = 3 акти (Ремесло / Патерн / Печатка), день = 3–4 справи + мета-крок + вечір із клівхенгером. Середнє проходження 5–6 год.
- **Механічний шар:** кабінет — «восьмий артефакт» попередника, 7 секретів (шухляда за ескізом; годинник на 4:07; іржавий ключик+олійниця; картотека; кривий портрет→трикутна щілина→шпилька з теки 3; сейф із кодом = рік, який гравець сам вивів; річ №6 «Не для світла» — загасити лампу). Механіка НІКОЛИ не гейтить сюжет — тільки темп і бонуси.
- **6 правил «кожен — Шерлок»:** відповідь з відкритих карток · три дороги до кожного висновку · діегетична драбина підказок (кіт, листи, «читачка» — без кнопки «підказка») · маленькі замки-один ключ · помилка=подія · три глибини правди (поверхнева всім / середня більшості / глибока для форумів).
- **6 кінцівок:** Атрибутор · Хранитель · Колекціонер · Шарлатан · Вигнаний · Секретна (нуль помилок → попередник приходить сам). Лічильники ведуться мовчки: Чесність / Цікавість / Борг.

## 7. ПАЙПЛАЙН 2D — СЦЕНИ, UI, ПЕРСОНАЖІ (Nano Banana Pro)

**Модель:** `gemini-3-pro-image` через `google-genai` SDK (`nbp.py` — готова обгортка). Чернетки — `gemini-2.5-flash-image` ($0.039 проти $0.134 за 2K). До 14 зображень у запиті (≈6 hi-fi об'єктів, 5 людей, 3 style-refs). Весь вивід має невидимий SynthID — у Steam декларуємо використання ШІ, це нормально.

**Чотири закони NBP:**
1. **EDIT, DON'T RE-ROLL.** Усе похідне (стани, емоції, шари сцени, кадри частин) — правкою готового кадру, не новою генерацією: 99% пікселів успадковуються, стиль не пливе.
2. **Матеріали, не оцінки.** «charred wood, wrought iron partially melted, ash in the cracks» працює; «beautiful, detailed» — ні.
3. **NBP інколи віддає JPEG-байти під ім'ям .png** — `nbp.py::_gen()` вже нормалізує через PIL. Робиш руками — пересохрани через PIL, інакше Godot МОВЧКИ не імпортує (нема .ctex).
4. Стиль-референси в кожному запиті (`style.py::STYLE_REFS`) — тримають «одну руку художника» на всій грі.

**Персонажі (клієнти бюро, Продавець, «читачка»):**
1. Концепт: `nbp.character(identity_ref, style_refs, prompt_body, out)` — рольова адресація зображень (Image 1 = ідентичність, Image 2.. = стиль). Або перший кидок без identity: детальний опис рис.
2. **Trait-locking:** зафіксуй риси дослівно («sharp grey eyes, heavy jaw, worn brown coat») і повторюй у КОЖНОМУ промпті цього персонажа без синонімів.
3. Стани/емоції: `nbp.emotion(canon, "opis", out)` — та сама людина, інша поза/вираз, правкою канону.
4. Для «однієї руки» Продавця через різні обличчя: `nbp.doppelganger(canon, wrong_detail, out)` — одна змінена деталь, решта успадковується. У Game2 це працює навпаки: різні обличчя, АЛЕ однакова рука (потертість під лівий великий палець) — рука описується дослівно однаково.
5. **IP-чек (П4)** кожного обличчя ДО продакшну.

**Сцени і розшарування (архітектура П2):**
1. Згенеруй ПОВНИЙ еталонний кадр екрана (кабінет цілком, у стилі, 2K–4K).
2. Правками «edit» знімай шари: «the same scene, drawer pulled out», «the same clock without hands», «only the hand, plain background», «the same scene, lamp extinguished, near-total darkness».
3. Елементи, що потрібні окремо (для руху) — генеруй на нейтральному тлі і вирізай (PIL/rembg — це обробка, не малювання кодом, дозволено).
4. UI-кіт: кнопки/панелі/рамки — теж картинками у всіх станах (звичайний/hover/натиснутий). Hover = домальований теплий відблиск, не програмний glow.

**Ціни:** концепт ≈$0.13 (2K), правка ≈$0.13, повний hero-предмет 2D-частина ≈$0.40.

## 8. ПАЙПЛАЙН 3D — ПРЕДМЕТИ (міст NBP→Meshy)

Повний рецепт із дослівними промптами — `pipeline/GUIDE_ITEM_CREATION.md`. Стислий закон:

**Проблема:** Meshy ліпить один суцільний меш — «предмет із кришкою» дає порожню шкаралупу. **Рішення:** NBP малює концепт → NBP правками робить «кадри частин» (тіло без кришки з видимим нутром + кришка ОКРЕМО, знята ЗГОРИ, «completely alone, nothing underneath») → кожен кадр у Meshy image-to-3d → складання в Godot.

**Параметри Meshy (вшиті в meshy.py):** `ai_model: "meshy-6"` (пінити!), `should_texture: true`, `enable_pbr: true`, `remove_lighting: true` (ОБОВ'ЯЗКОВО — інакше запечене світло б'ється зі свічковим у грі), `target_polycount: 8000` тіло / `4000` кришка (hero до 15000), `origin_at: "bottom"`, `texture_prompt` (+10 кр, того варті). Промпт ≤600 символів. **Негативних промптів НЕ ІСНУЄ** — описуй бажане. URL результату ТИМЧАСОВІ — качай GLB одразу.

**Головний закон Meshy: ліпить УСЕ, що бачить у кадрі.** Привид тіла під кришкою → обріж картинку по край кришки (PIL), не переганяй.

**Фурнітура на стику** (накидний замок, ремінець): розділяй ще НА КАДРАХ правками — «REMOVE the upper hinged strap half...» з тіла, «ADD the upper half of the front iron clasp...» на кришку. Тоді верхня половина замка їде вгору разом із кришкою (це був баг, який зловив Віктор).

**Оптимізація під Godot:**
```bash
npx -y @gltf-transform/cli optimize in.glb out.glb --compress false --texture-compress auto --texture-size 2048
```
**`--compress false` — святе:** дефолтний meshopt Godot НЕ підтримує — імпорт мовчки падає (valid=false), чорний екран, втрачений вечір. 33МБ → ~15МБ без видимих втрат.

**Складання в Godot — завжди математика, ніколи «на око»** (шаблон: test_casket.gd у PawnShop):
1. масштаб кришки: її ширина X = ширині X тіла;
2. нормалізація кришки до завіси: зсув на -aabb.min (низ y=0, задній край z=0, центр x);
3. завіса (Node3D-півот) на задньому верхньому краї тіла, утоплення 3–4% висоти;
4. відкривання — tween повороту півота по X.

**Тонкі деталі** (стрілки, дріт) Meshy завалює — домоделюй примітивами в Godot. **Дзеркала/скло** — заміняй площину власним матеріалом. Перевірка результату — очима В КАДРІ ГРИ (тест-сцена+скріншот), не в прев'ю Meshy.

## 10. GODOT — ВЕРСІЯ, ГРАБЛІ, ВЕРИФІКАЦІЯ

**Godot 4.7 stable, GDScript.** Проєкт компілюється з warnings-as-errors: інференс типу з Variant — помилка. `var x := dict.get(...)` НЕ компілюється → пиши явний тип `var x: String = ...`.

**Граблі, оплачені кров'ю:**
- Кеш імпорту отруюється битим ассетом: заміняй файли під НОВИМ іменем (v2, v3...), не поверх.
- `.gdignore` у папки, які Godot не має чіпати.
- Async-гонки UI: кожна корутина з `await` перевіряє `ui_token` (лічильник поколінь) після повернення — інакше стара корутина перемалює новий екран (баг «питання після світанку»).
- Оверлеї перекривають ввід: контейнер кнопок — `move_child(btns, get_child_count()-1)` наверх (баг «зависло на хустці»).
- `_say()`-подібні функції не мають викликати самі себе через сигнали (була саморекурсія regex).

**Верифікаційний цикл (повний, без машини Віктора):**
```bash
G=/tmp/Godot_v4.7-stable_linux.x86_64
$G --headless --path . --import                      # 1. імпорт ассетів + помилки компіляції
$G --headless --path . --script res://autotest.gd     # 2. сценарні тести (t_press/t_state хуки)
xvfb-run -a $G --path . --rendering-driver opengl3 &  # 3. реальний рендер
sleep 8 && import -window root shot.png               #    скріншот — ДИВИСЬ ОЧИМА
xdotool mousemove X Y click 1                         # 4. РЕАЛЬНІ кліки мишею (не pressed.emit!)
```
Правило: кожен екран перевіряється скріншотом (дивись очима як гравець) і реальними кліками по всіх інтерактивних зонах. Синтетичні тести доповнюють, не заміняють.
